# 试卷题目识别规范（v2）

> 本文件是试卷题目识别项目的**唯一正本**。skill（`.workbuddy/skills/cuotiji-recognize/SKILL.md`）与一切识别路径（对话内 / API 保底 / 云服务）都引用此文件，规范修订只改这里。

## 任务定义

输入：一张试卷 / 练习页照片。

**默认动作是「整页全量识别」——把页面上所有题目全部识别、全部入库，不做任何筛选。**

⚠️ **识别层不去重**：同一份卷若被拍成多张有重叠的照片（如「第一二单元素养卷」与「乘法综合练习」
在接缝处重复拍了「4. 写出综合算式」），重叠区的同一道题会入库两次 —— 这是**照实记录**，
别在识别时自作主张跳题或合并。去重在**成卷层**做：`engine/paper.py` 合卷时按内容指纹
（题干 + 选项去空白）在每个大题内部只印一份，被剔除的题会在 stderr 打 `[去重]` 日志；
`--keep-dup` 可关闭去重。题库（`data/questions/`）始终保持全量。

**输出范围（v2 收窄）——只做题目识别 + 题型分类。** 结构化对象仅含：
题干（文字片段 + 公式 LaTeX + 图形引用）、选项、题型、板块、来源坐标、置信度。

**以下一律不产出**（属于分析或错题本功能，不属于"识别"）：
标准答案、解析、学生手写作答、批改笔迹、对错判定、知识点/难度标签、重做记录、自由备注。

输出：按 schema v2 的结构化 JSON，每道题一个文件，存入 `data/questions/`；对应原图裁剪存入 `data/crops/`。

## 铁律（违反即无效输出）

1. **禁止臆造**：看不清、被遮挡、模糊的内容必须输出 `[?]` 标记占位，并把对应置信度置 ≤0.5。被篡改的题比缺失的题危害更大——宁可留 `[?]` 交人工，不可编一个"看起来对"的答案。
2. **不做语义补全**：题目文字照实转写，不修正原文中的笔误（印刷体原文如此就照写）；数学符号转 LaTeX 时只做格式转换，不改数值。
3. **只输出题目本身**：不产出答案、解析、对错判定、知识点标签；学生手写作答与红笔批改**不进 JSON**（它们不是题目内容）。
4. **置信度诚实**：印刷清晰 0.9+；略模糊/字号小 0.7–0.9；明显模糊、被笔迹覆盖、依赖推测 ≤0.5。不确定就低报，校对层会置顶低置信度项。
5. **图形优先裁剪**：所有图形默认走 `state: "crop"`（裁原图保留）。只有当题干中函数表达式清晰完整、可零歧义提取时才额外填 `expr` 字段；几何约束 JSON 一律不填（延后启用）。
   图形必须**单独裁成子图**（`<题目id>-fig<N>.jpg`），`figure.src` 指向它——**不能指向整题裁剪图**：
   右栏会把 `figure` 当图片直接显示，指整题图会导致题干文字在还原区里重复出现一遍。
6. **卷面印刷序号必须剔除**：题号（`（1）` / `12.` / `①②`）是元数据，不进题干、也不留在裁剪图里——题干从正文第一个字开始，裁剪从正文第一个墨迹像素开始。序号本身不丢弃，记入 `source.printed_no`（实测漏掉过一次：q-20260930-050 的裁剪左边缘留了半个「（」，用户发现后返工）。

## 切题规则

- 以**最小印刷题号**（1. / 2. / （1）（2）/ ①②）为切分依据；跨栏、跨页的题目合并为一题，`source` 记录所有来源区块。题号只用于切分，**不写进 `stem`**（见铁律 6）。
- **切分粒度：印刷小题号出现几次就成几题**（2026-10-01 用户反馈后修订，**原「小题不自足就合并」的规则作废**）。
  选择题每小问有自己的题干与 4 个选项、填空题每小问自带一道题，固然各自成题；**共享同一指令的小题
  也照样各自成题**——(1)(2)(3)… 各算一题（实测：第 3 份卷「6. 选择 (1)(2)」、2026-10-01 卷
  「1、选择题 (1)-(6)」「2、填空题 (1)-(6)」「4. 写出综合算式 (1)(2)」都按此切分）。
  **原规则作废的原因**：合并会连**版式信息**一起丢掉。「写出综合算式」原件是 **2 行 2 列**——
  (1)(2) 各占一列、每列两行已知算式、下方一条答题横线：
  `(1) 63÷9=7 / 147-7=140` 与 `(2) 367+26=393 / 494-393=101`。
- ⚠️ **一个小题可以印成多行，别把它的第二行当成新题**（2026-10-01 二次返工，同一处错两次）：
  印刷题号只在**小题首行**出现（或整段只印一次），第二个及以后的行 `printed_no` 是**空串**
  —— 那就是「不是新小题」的信号。实测把上面四条算式**各当一题**入库，卷详情页里
  (1) 的第二条算式被 (2) 隔到了下一行，看起来就是「一题被拆开了」（用户指出）。
  正确做法：**按印刷题号成题**，题内多行用换行表示（见下一条），上例就是 **2 题**。
- **题干内的多行用换行（`\n`）表示**（schema 不变，仍是一条 text 片段）：卷面上同一小题印成两行时
  （如「写出综合算式」的两条算式、应用题题干下方的「①估算法：/②计算法：」），在一条 text 里用换行分隔。
  渲染层负责换行——校对页 `frag()` 与组卷 `seg_html()` 都把换行换成 `<br>`。
  **不要**为了换行拆成多个片段：片段是「文字 / 公式 / 图形」的混排单位，不是行单位。
- **小题共享的上级指令不重复写进各题 `stem`**：它属于板块层级，由 `section` 承载
  （组卷时作为大题标题，如「四、写出综合算式」）。只有指令仅作用于一部分题、`section` 装不下时，
  才写进这些题的 stem。
- `printed_no` 记**该题自己的**印刷题号；同一指令下的小题按卷面所见记 `(1)` `(2)` …，
  卷面没印的记空串（实测：2026-10-01 卷「写出综合算式」只有 (1)(2) 两个题号，
  另两行是它们的**第二行**，不是新题 —— 空串的含义是「续行」，见上面第 2 条）。
- 选择题的选项属于题干 `options`，不单独成题。
- 学生作答、红笔批改不单独成题，也不写进 JSON。
- 完全无法判断归属的碎片：并入相邻题目，并在该题 stem 末尾以 `[?]` 标记归属存疑。
- **只有标题、没有任何小题内容的板块**（实测：「5. 列式计算。」后面直接接下一部分）**不入库**——不要造一个空题，在汇报里单独说明。
- **作答位置标签不等于小题号，但它是卷面印刷内容，必须收进题干**（2026-10-01 第 7 份卷，判断修正过一次）：
  卷面在题干下方印的「①估算法：」「②计算法：」，下面只有学生笔迹、没有独立的印刷题目内容。判定分两步：
  ① **先判是不是小题**：带独立印刷题目内容 → 各自成题（如「写出综合算式」的 (1)(2) 各带两条算式）；
    只是给书写留位置 → **不拆题**，并入同题。
  ② **再判收不收进 stem**：这些标签**是卷面上真实存在的印刷文字**，不收就是漏识别
    （用户反馈：「这一题下面有指定了两个解法的名词被丢了」）。所以**要写进 stem**——
    题干末按卷面顺序接 `\n①估算法：\n②计算法：`（见「题干内多行用换行」一条）。
    上一轮把它们判成「只有标签、无小题内容」而丢进 `review_note`，是错的：那条规则针对的是
    **板块标题**（如「5. 列式计算。」后面空着），不是题内的印刷标签。
  ③ 裁剪范围同步**下延到覆盖这些标签**——题区 = 该题在卷面上的**全部印刷范围**，左右对照才对得起来。
- 板块标题按卷面层级记，层级用「·」连接（如 `第二部分 概念 · 1、选择题`）；上级标题被裁掉、看不见时 `section` 留空串，**不要猜**。

## 手写笔迹处理（v2）

学生手写作答与红笔批改**不是识别对象**，一律不写进 JSON。但它们确实印在卷面上，处理原则：

- 笔迹与题干不重叠 → 直接忽略。
- 笔迹覆盖 / 遮挡题干（答案写在括号里、划改盖住数字、红笔压在公式上）→ 只转写可辨认的题干部分，
  被遮挡处标 `[?]`、置信度 ≤0.5。**不得**把笔迹内容当成题目文字。
- 裁剪范围**按题目本身（印刷内容）定界**；笔迹若落在框内就自然可见，**不为了「包住笔迹」而把框撑大**。
  理由（2026-10-01 第 7 份卷实测）：手写卷上笔迹能远超题区——某题题干只占 90px 高，学生的两种解法
  却一直写到下方 390px 处；按「包含所有笔迹」拟合会把整块作答区（甚至邻题作答）框进来，
  左栏对照图上题目反而被淹没。判据是**笔迹不被切掉**（落在框内的部分完整），不是**所有笔迹都在框内**。
- 无论框怎么划，笔迹**都不得**被当成题目内容转写。

## LaTeX 转写规则

- 行内公式用 `t: "latex"` 独立片段；与文字片段按阅读顺序混合成 `stem` 数组。
- 常用结构：分数 `\frac{a}{b}`、根号 `\sqrt{}`、角度 `\angle`、三角形 `\triangle`、度 `°`（直接用度符号）。
- 简单算式（如 `3x + 5 = 20`）也用 `t: "latex"`，保持一致性。
- **占位方框 / 圆圈 / 几何记号**：中文题干里的填空方框、判断圆圈、三角形、五角星（含实心变体）**照实转写为 `□` `○` `△` `☆` `■` `●` `▲` `★` 字符**，留在 `text` 片段里。
  渲染层负责把它们画成与汉字协调的等宽形状，**不要自行改写**（别写成下划线 `____`、空括号 `( )` 或 LaTeX `\square`／`\bigcirc`）。
  （例外：符号本身就是式子里的运算符时——如比大小题 `102×3 ○ 500`——那属于 `latex` 片段，照实写成 `\bigcirc`，见 q-20260930-044。）
  （实测：字体自带的这些字形明显小于汉字且大小不一，用户先后反馈过 q-20260930-050 的方框、q-20261001-011 的三角形与五角星"小"。）
- **下划线留空**：卷面用下划线留空的（`250×4 的积的末尾有____个 0`），照实转写为 **4 个半角下划线 `____`**；
  不要改成 `（　　）`，也不要写成一串全角空格。圆括号留空仍写 `（　　）`（两种留空方式在卷面上本来就不同）。
- **插图内部的文字不进 `stem`**（如微波炉图里的「每台 398 元」、泳道图里的「50 米」）：图已随裁剪保留，
  再把图文混写进题干会让同一信息出现两遍。将来若真要「纯文字也能读懂题目」，另开字段，不要塞 stem。
- 整个表达式已用 LaTeX 时，比较符号的圆圈写 `\bigcirc`（如 `102\times3\ \bigcirc\ 500`），由 KaTeX 渲染。

## 输出文件规范

- 题目 JSON：`data/questions/q-<YYYYMMDD>-<NNN>.json`（NNN 当天递增）。
- 题区裁剪图：`data/crops/<题目id>.jpg`；题内插图**另行单独裁剪**为 `data/crops/<题目id>-fig<N>.jpg`。
- 整卷原图存 `data/benchmark/`（命名 `YYYY-MM-DD-<来源描述>.jpg`），`source.file` 记录该文件名。
- JSON 必须通过 schema v2 校验（`engine/db.py import` 会校验关键字段）。

## 裁剪定位方法（实测有效，务必按此流程）

**每道题都要裁剪题区**（不只是含图形的题）——校对页的左栏就是靠它做左右对照。

坐标必须用**数据驱动方式**定位，禁止凭肉眼估百分比（实测：目测会整体偏移一整行）。

**核心原则：先给每题划一个「只含本题内容」的搜索窗口，再在窗口内自动拟合内容包围盒。**
窗口负责排除不属于本题的东西（板块标题、行首题号、相邻列），拟合负责贴合内容、
不切字也不留大片空白。

### 0. 先按颜色分离「印刷体」与「笔迹」—— 笔迹多的卷必做（2026-10-01 第 6 份卷新增）

**灰度二值化在笔迹多的卷子上会失效**：红笔批改 + 铅笔作答会把题目行、作答行、甚至邻题
连成一条几十上百像素的大带，行投影看不出任何行边界（第 6 份卷实测：口算三行 + 学生笔迹
连成一条 156px 高的带）。定位题目行时**只用「印刷黑」掩膜**：

```python
lum = (R*299 + G*587 + B*114) // 1000          # 注意用 int32，int16 会溢出！
PRINT = (lum < 118) & (max(R,G,B) - min(R,G,B) < 42)   # 印刷黑：暗 + 低彩度
```
红笔（`R - max(G,B) > 35`）与铅笔（浅灰）据此被排除。实测**印刷行核的墨迹密度 50–140，
而笔迹带只有 5–25**，所以再叠一个密度阈值（`prof >= thr`，thr 取 15–22）找行核即可稳稳定位。

`tools/page_layout_probe.py` 就是干这个的：输入若干「一列里只含某一道题」的窗口，
输出每段的**行核 y 区间 + 该行内的列段 x 区间**。配合打印密度曲线（逐行打 `#`）看极小值，
行边界就确定了。

**定位与定界都可以只用「印刷黑」掩膜**（不必把灰度掩膜换回来）：只用它定出**题目本身的包围盒**，
再按这个盒去裁**彩色原图**——框内的笔迹照样显示（左栏对照要看真实卷面），但框不会被笔迹撑走形。
第 6 份卷笔迹尚可、用灰度掩膜无妨；第 7 份卷笔迹密到题题相叠，就必须用印刷掩膜定界
（否则包围盒会被邻题作答带跑偏，实测某题从 90px 高撑到 390px）。判据见「手写笔迹处理」。

### 1. 逐列检测行带 —— 禁止用「全页统一行带」（踩过的坑）

扫描件普遍有几度的倾斜，实测同一行的列 1 与列 4 纵向差 40+px。全页行投影会把
不同列的错位行合并成一条大带（实测 585–704 一条带里塞了板块标题 + 4 列的 3 个错位行），
用它裁剪必然切字。**必须按列分别做行投影**：`ink[:, x_col0:x_col1].sum(axis=1)`。

### 2. 排除板块标题

板块标题（「1. 直接写出得数」）与首行题目可能首尾相接、无空白间隙，行带会连成一片。
做法：先在标题的 x 范围内测出标题行带，再对每列行带做重叠判定——与标题行带纵向重叠
超过自身高度 30% 的行带丢弃（阈值取 30% 是为了不误伤列 4 那种「首行比标题还高」的情况）。

### 3. 剔除行首印刷题号

在题目第一行的行带内做列投影，找到「序号」与其后正文之间的间隙（≥8px，而字内间隙
通常 ≤6px）；窗口左边界取序号最后一个墨迹像素 +1（**不要取间隙中点**：实测换行后
第二行可能比第一行正文更靠左，取中点会切掉第二行首字）。

⚠️ **题号本身可能被拆成多个墨迹 run**（「(」「2」「)」各一段，run 间间隙 3–6px，与字内间隙同级）。
必须取**全部题号 run 的末像素**，不能只取第一个 run 的末像素——实测 q-20260930-056 的「(2)」跨
204–235 / 238–249 两段，只取 235 导致裁剪左边缘残留半个「)」。稳妥做法：先按 8px 间隙合并 run，
再判定「这一段整体是否为题号」（宽度约 40–50px、位于行首、其后间隙 ≥8px）。

⚠️⚠️ **续行 / 选项行可能比题号还靠左（顶格）——此时绝不能按「题号末像素+1」裁**（2026-10-01 实测踩到）。
该卷的选择题首行是缩进的（题号 x178–216、正文 223–231），但**选项行与续行顶格**：
`A.` 起点 x≈164–171，比题号左 10–50px；按「题号末+1」（≈211）裁会把「A. 26」这类选项切掉一半。
做法：**把该题所有内容行（首行 + 续行 + 选项行）都做列投影**，比较首行题号左边界与各续行左起点，
续行更靠左就**取全部行的最小墨迹 x 作左边界**（本题实测取 163–169）。代价是卷面题号完整留在裁剪图里——
**取舍原则：题号留在图里只是观感问题，切掉选项是内容错误**。这种情况必须写进
`source.review_note`（`crop_reviewed = true`），把取舍理由留档。

### 4. 自动拟合 + 留白

窗口内取墨迹的最小外接矩形，四边各留 8px（被剔除题号的那一侧左留白取 0，否则会把
半个题号又带回来）。

### 5. 列边界取相邻两列内容的「间隙中点」

边界若落在内容里会切掉本列首字符；相邻列边界若相互重叠，会把邻列内容带进裁剪。

### 6. 裁剪后必须自检（两道）

- **程序自检**：`python engine/crop_check.py` —— 逐题检查四条边 1px 处的墨迹像素数，
  把「切字 / 标题残留 / 序号残留」自动暴露出来。它同时按 `figure.bbox` 检查题内插图子图
  （显示为 `q-xxxxx#fig1`）。**这一步是本规范里曾经缺失的工序**，
  q-20260930-050 的序号残留就是漏了它才流到用户面前。
- **目视复核**：把裁剪拼成校验图（`data/samples/_crops_check*.jpg`）用 Read 看一遍。

手写卷的边沿一定有学生笔迹越界、被剔除题号的那条边外侧一定有墨迹，这两类告警经人工
放大核对确认题面完整后，在 JSON 里置 `source.crop_reviewed = true` 并写明
`source.review_note`，自检工具即不再对其告警（避免告警疲劳）。

### 7. 题内插图单独裁子图

题干含插图（示意图、实物图、几何图）时，在题区裁剪之外**额外裁剪插图本身**，存
`data/crops/<题目id>-fig<N>.jpg`，并把 `figure.src` 指向它、`figure.bbox` 记原图坐标。

- 定界方法：先取插图所在的**行带**（题区内做行投影，插图通常独占一段、与题干文字行之间有明显空隙），
  再在该行带内做列投影取列范围（插图与题干文字之间一般有 60px 以上的大间隙，用 `gap=60` 一次即分干净）。
- 裁完同样过自检（`crop_check.py` 会按 `figure.bbox` 报告四条边的余量）。
- 实测：q-20260930-055 的泳道图 `[978,711,1335,963]`、q-20260930-056 的电梯标识 `[1069,1096,1329,1336]`。
- 漏做的后果：校对页右栏的"题内图片"位置只能显示一个占位标签，用户看不到图（用户反馈过「为什么题目中的图片没有」）。

图片处理用隔离环境：`C:\Users\1\.workbuddy\binaries\python\envs\default\Scripts\python.exe`（已装 Pillow / numpy）。

## schema v2

**只有这些字段。** v1 的 `answer` / `analysis` / `student_answer` / `annotations` / `judgement` /
`tags` / `note` / `redo_history` 已全部移除——它们属于「分析」与「错题本」范畴，不在识别职责内。
（v1 原件完整备份在 `data/questions_v1_backup/`，迁移脚本 `tools/migrate_v1_to_v2.py`。）

```json
{
  "schema_version": 2,
  "id": "q-20260930-001",
  "no": 17,
  "section": "三、解答题",
  "type": "geometry",
  "stem": [
    {"t": "text", "v": "如图，在直角三角形 ABC 中，"},
    {"t": "latex", "v": "\\angle BAC = 90°,\\ AB = 4,\\ AC = 3"},
    {"t": "figure", "state": "crop", "src": "q-20260930-001-fig1.jpg", "bbox": [978, 711, 1335, 963],
     "expr": null, "geometry": null, "confidence": 0.62}
  ],
  "options": [],
  "source": {"file": "期中卷.jpg", "page": 2, "bbox": [0, 0, 0, 0], "crop": "q-20260930-001.jpg",
             "printed_no": "（1）", "crop_reviewed": false, "review_note": ""},
  "confidence": {"stem": 0.97, "options": null, "figure": 0.62},
  "created_at": "2026-09-30T22:00:00+08:00",
  "updated_at": "2026-09-30T22:00:00+08:00"
}
```

字段约定：
- `no`：题号（整数，按整页阅读顺序，含卷面上无印刷号的题）。
- `section`：题目所属板块标题（如「一、算一算」），无则空串。
- `type`：`choice`（选择题）/ `fill`（填空）/ `calculate`（口算·直接计算）/ `solve`（解答·竖式·递等式）/ `geometry`（几何）/ `proof`（证明）/ `other`。**这是 schema 里唯一的"分析"字段。**
- `stem`：内容片段数组，按阅读顺序。`t` = `text`（文字，不可辨处写 `[?]`）/ `latex`（公式）/ `figure`（图形）。
- `options`：选择题选项（片段数组）；非选择题为 `[]`。
- `figure.state`：`crop`（裁原图，默认）/ `expr`（函数表达式）/ `geometry`，渲染失败自动回退 `crop`。
- `figure.src`：**该插图自己的裁剪子图**文件名（`data/crops/<题目id>-fig<N>.jpg`），校对页右栏据此显示图片。
  绝不可写整题裁剪图（`source.crop`）——那会把题干文字并进还原区重复显示一遍。
- `figure.bbox`：插图在原图上的像素坐标 `[左, 上, 右, 下]`，与 `source.bbox` 同一坐标系；
  供 `crop_check.py` 检查插图是否被切边、以及将来重裁。
- `figure.caption`（可选）：插图的**一句话文字说明**（如「图：微波炉，每台 398 元」）。
  渲染时印在图下方的小字里（校对页与卷面都印）。热敏打印/复印会把图糊掉，写死一句说明，
  学生照文字也能读懂题意。只描述**看得见的画面**，别写解题提示、别写答案。
- `source.bbox`：原图上的像素坐标 `[左, 上, 右, 下]`，用于回看与重裁。
- `source.printed_no`：卷面印刷题号（如 `（1）`、`12.`），**已从题干和裁剪中剔除**，仅留档；卷面无题号则省略该字段。
- `source.paper` / `source.paper_title` / `source.paper_page`：**只有「一份卷拍成多张照片」时才写**（可选字段）。
  `source.paper` 是卷标识，取值形如 `2026-10-01-第2单元练习卷.jpg`（**虚拟文件名**，不必真实存在，
  只为复用「按文件名推导日期/标题/slug」的逻辑）；同一份卷的所有照片、所有题写**同一个值**。
  `source.paper_title` 是卷面页眉上的印刷卷名（如 `第2单元练习卷（静安名校）`、
  `数学三年级第一学期第一、二单元素养卷`）。
  `source.paper_page` 是该题所在照片在**卷内的页序**（1 起，同一张照片的题共用同一个值）。
  渲染层与成卷的分组键统一是 `source.paper or source.file`：标了就合并成**一份**卷
  （多张原图列在同一个卷详情页里、打印成同一份卷面），没标就仍按单张照片分组。
  卷内排序 = 照片页序（`paper_page`，未标时退回按文件名）→ 卷内 `no`。
  ⚠️ **照片文件名顺序天然等于页序时可不标 `paper_page`**（如 `-p1..-p4`）；文件名顺序与页序
  **相反时必须标** —— 字符串排序里 `…-应用.jpg` 的 `-`(0x2D) 会跑到 `…卷.jpg` 的 `.`(0x2E) 前面，
  不标就会把「第三部分 应用」排到「第一部分 计算」之前。
  ⚠️ 合并后同一大题在不同照片上列数可能不同（如「四、递等式计算」p1 是 3 列、p2 是 2 列），
  所以 `paper.py` 的 `infer_cols()` 是**按照片分别聚类再取最小**，不是把所有题一起聚类。
  **判「这张照片是不是同一份卷」的三条依据**（第一二单元素养卷就补合过第三次）：
  ① 板块接得上（「第一部分 计算」→「第二部分 概念」→「第三部分 应用」）；
  ② 接缝处有**内容重叠**（卷子下半段的续拍会再把上一张底部那几题拍一遍）；
  ③ 续拍的那张**没有卷头**（只有真正的第一张印着卷名/班级/姓名栏）。
  三条里前两条是硬证据；只看「手写笔迹不同」不能否掉 —— 同一份卷的不同照片可能一张有学生作答、
  一张只有老师批注（甚至完全空白），那是拍照时的材料状态，与「是不是同一份卷」无关。
- `source.crop_reviewed` / `source.review_note`：裁剪边界告警是否已经人工核对确认及理由，见「裁剪定位方法」第 6 条。
- `confidence`：只对 `stem` / `options` / `figure` 三个键；低于 0.7 会在校对页置顶提醒。
- 时间戳：ISO 8601 带时区。

**升级 schema 的唯一途径**：改本文件 → 升 `schema_version` → 同步改 `engine/db.py` 与 `engine/render.py`
的校验/渲染 → 写迁移脚本（参照 `tools/migrate_v1_to_v2.py`：先备份、再转换、可回滚）。

## 识别完成后（对话内路径）

1. JSON 写入 `data/questions/`，题区裁剪写入 `data/crops/`（`source.bbox` 记像素坐标，`source.crop` 记裁剪文件名，如 `q-20260930-001.jpg`）；题干含插图时**另裁插图子图**并写进 `figure.src`（见「裁剪定位方法」第 7 条）。
2. **跑裁剪自检**：`engine/crop_check.py`——把可疑裁剪处理到零（或逐张核对后标 `source.crop_reviewed`）。
3. 运行 `engine/db.py import data/questions` 入库（SQLite）。
4. 运行 `engine/render.py data/questions` 生成校对页（HTML+KaTeX）。
5. 打开校对页给用户，汇报：**识别题目总数**（按板块分列）、题型分布、低置信度项、`[?]` 标记位置。
6. 整页所有题目全部入库，不做筛选（不筛错题、不按对错过滤）。
